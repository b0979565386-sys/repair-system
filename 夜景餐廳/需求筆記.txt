夜景餐廳口袋名單｜需求筆記（示範資料，全為虛構）

■ 背景
- 用途：私人旅遊時，想找有夜景的餐廳。
- 目前問題：看到的推薦散在筆記、相簿和聊天紀錄裡，出發前很難快速比較哪家夜景好、要不要先訂位。
- 想做一個「夜景餐廳口袋名單」：打開就能用、不用登入，把想去或去過的夜景餐廳整理在同一份清單，可以依地區、夜景類型、價位篩選。

■ 要登記的資訊
基本與地點
- 餐廳名稱
- 城市或地區
- 地址
- 餐廳網址
夜景特色
- 夜景類型（例如：城市夜景、海景、山景、河景、其他；選項清單待確認）
- 樓層或高度（例如：38 樓、山上；填寫格式待確認）
- 靠窗座位好不好訂：容易、普通、困難
價位與訂位
- 每人價位區間（區間與幣別待確認，旅遊可能在國外）
- 是否需要訂位：需要、建議、不用
- 營業時間
評價與推薦
- 評分（1～5 分；還沒去過可留空）
- 推薦理由
- 推薦人（只填虛構代稱，例如「朋友 A」「旅遊書」）
- 去過的日期（還沒去過可留空）
系統欄位
- 登記時間、最後修改時間（系統自動產生）

■ 誰能做什麼
- 不用登入：任何打開網頁的人都能新增、查看、修改、刪除夜景餐廳，並依條件篩選。
- 原本「只有我自己能看」的需求已改為不用登入（需求方確認：接受資料公開，換取不用登入）。
- 沒有管理者角色；網址只分享給信任的人。

■ 資料安全
- 這是示範，餐廳名稱、地址、推薦人都用虛構資料，不放真實姓名，也不放客戶或廠商的真實資料。
- 只能使用 Supabase 的 publishable key；secret key（含 service_role）不可以寫進任何檔案，也不可以上傳到 GitHub。
- 不用登入的代價：網頁發佈在公開的 GitHub Pages，任何拿到網址的人都能看到、修改、刪除整份清單。
  - 只放可以公開的內容；去過的日期與地點屬於個人行程資訊，填之前要想清楚。
  - 資料可能被誤刪或亂改，需要時可在 Supabase 後台匯出備份。
- 資料表仍啟用資料列安全（RLS），明確寫出允許的讀取、新增、修改、刪除；不開放一次清空整張表（TRUNCATE）。
- CHECK 限制欄位值與字數，避免亂填或塞入過長內容。
- id 與時間欄位由資料庫自動產生，網頁不能指定。

■ 還沒決定的事
- 是否需要備份或防止誤刪（例如定期匯出、只允許新增不允許刪除）。
- 離線時要不要能查看清單（目前 PWA 離線只能開啟畫面，不保存清單資料）。
- 夜景類型的選項清單。
- 價位區間怎麼分、要不要記錄幣別。
- 樓層或高度的填寫格式。
- 是否要區分「想去」和「去過」兩種狀態（目前用「去過的日期」是否留空判斷）。
- 是否需要地圖、照片或匯出功能（本次不做）。

■ 交付物
- 網頁：夜景餐廳清單（不用登入，直接新增、修改、刪除、篩選），做成 PWA，可安裝到手機主畫面，用 GitHub Pages 發佈
- Supabase：資料表與存取規則（建表 SQL）
