夜景餐廳口袋名單｜需求筆記（示範資料，全為虛構）

■ 背景
- 用途：在臺灣旅遊時，想找有夜景的餐廳。範圍只限臺灣（含澎湖、金門、馬祖），不收國外的餐廳。需求方確認「全臺灣就好」：東沙、南沙等遠方離島不納入。
- 目前問題：看到的推薦散在筆記、相簿和聊天紀錄裡，出發前很難快速比較哪家夜景好、要不要先訂位。
- 想做一個「夜景餐廳口袋名單」：打開就能用、不用登入，把想去或去過的夜景餐廳整理在同一份清單，可以依地區、夜景類型、價位篩選。

■ 要登記的資訊
基本與地點
- 餐廳名稱
- 縣市（只能選臺灣 22 個縣市，例如臺北市、高雄市、澎湖縣）
- 地址
- 餐廳網址
夜景特色
- 夜景類型（例如：城市夜景、海景、山景、河景、其他；選項清單待確認）
- 樓層或高度（例如：38 樓、山上；填寫格式待確認）
- 靠窗座位好不好訂：容易、普通、困難
價位與訂位
- 每人價位區間（新台幣：1000 元以下、1000～2000 元、2000 元以上；區間待確認）
- 是否需要訂位：需要、建議、不用
- 營業時間
評價與推薦
- 評分（1～5 分；還沒去過可留空）
- 推薦理由
- 推薦人（只填虛構代稱，例如「朋友 A」「旅遊書」）
- 去過的日期（還沒去過可留空）
地圖位置
- 緯度、經度（可留空；兩個都填或都不填；必須在臺灣範圍內。搜尋景點會自動帶入，也可以在表單的地圖上點選）
照片
- 每家最多 6 張（檔案存在 Supabase Storage，資料表只記檔名）
系統欄位
- 登記時間、最後修改時間（系統自動產生）

■ 誰能做什麼
- 不用登入：任何打開網頁的人都能新增、查看、修改、刪除夜景餐廳，並依條件篩選。
- 原本「只有我自己能看」的需求已改為不用登入（需求方確認：接受資料公開，換取不用登入）。
- 沒有管理者角色；網址只分享給信任的人。
- 任何人都能在新增或修改時加入、移除照片；清單卡片與地圖彈出視窗會顯示第一張照片，點了可以全螢幕左右滑動看全部。
- 任何人都能匯出清單：可選「目前篩選結果」或「全部」，格式為 CSV（Excel、Google 試算表可開）或 JSON（完整備份）；照片只匯出網址。
- 任何人都能在「地圖」檢視看到有位置的餐廳（黃色＝想去、綠色＝去過），點標記會進入店家頁面（照片、完整資訊、導航、修改）；畫面上不顯示經緯度；「我的位置」只在按下時定位，不會儲存。
- 任何人都能用「搜尋臺灣景點」查詢臺灣的真實地點（只回傳臺灣的結果，並自動對應縣市），按「加入清單」把名稱、城市、地址（有的話還有網址）帶入新增表單，再補上夜景類型等資訊後儲存。

■ 資料安全
- 這是示範，餐廳名稱、地址、推薦人都用虛構資料，不放真實姓名，也不放客戶或廠商的真實資料。
- 只能使用 Supabase 的 publishable key；secret key（含 service_role）不可以寫進任何檔案，也不可以上傳到 GitHub。
- 不用登入的代價：網頁發佈在公開的 GitHub Pages，任何拿到網址的人都能看到、修改、刪除整份清單。
  - 只放可以公開的內容；去過的日期與地點屬於個人行程資訊，填之前要想清楚。
  - 資料可能被誤刪或亂改，需要時可在 Supabase 後台匯出備份。
- 資料表仍啟用資料列安全（RLS），明確寫出允許的讀取、新增、修改、刪除；不開放一次清空整張表（TRUNCATE）。
- CHECK 限制欄位值與字數，避免亂填或塞入過長內容。
- id 與時間欄位由資料庫自動產生，網頁不能指定。
- 照片存在公開的 Supabase Storage 儲存桶（night-view-photos）：任何拿到網址的人都能看到、上傳、刪除照片。
  - 上傳前網頁會把照片縮到長邊 1600 像素、重新存成 JPEG，同時移除照片裡的 EXIF（含拍攝定位）資訊。
  - 儲存桶只接受 JPEG、每張最多 2 MB；檔名必須是網頁產生的「UUID.jpg」，不能建立資料夾或覆蓋別的檔案。
  - 刪除餐廳或移除照片時，會一併刪除 Storage 裡的檔案；若上傳後資料沒存成功，會把剛上傳的照片刪掉。
  - 照片可能拍到人臉或私人資訊，上傳前要想清楚。
- 匯出檔在瀏覽器產生，不經過伺服器；CSV 中以 = + - @ 開頭的內容會在前面加 ' ，避免 Excel 把有人亂填的內容當成公式執行。
- 匯出的檔案包含整份清單與照片網址，分享前要想清楚。
- 地圖使用 Leaflet 與 OpenStreetMap 圖磚（免金鑰）：看地圖時，畫面所在區域的圖磚會向 OpenStreetMap 伺服器下載；圖磚不離線快取，離線時地圖不會顯示。
- 「我的位置」需要瀏覽器定位權限，位置只用來移動地圖，不會送到資料庫。
- 搜尋景點使用 OpenStreetMap 的 Nominatim 服務（免金鑰）：輸入的關鍵字會送到 OpenStreetMap 的伺服器；搜尋結果不存進資料庫，也不被離線快取。
  - 依服務規範：只在按下搜尋時查詢、每秒最多一次，並在結果下方標示「© OpenStreetMap 貢獻者」。

■ 還沒決定的事
- 是否需要備份或防止誤刪（例如定期匯出、只允許新增不允許刪除）。
- 離線時要不要能查看清單（目前 PWA 離線只能開啟畫面，不保存清單資料）。
- 夜景類型的選項清單。
- 價位區間怎麼分（幣別已確定為新台幣）。
- 樓層或高度的填寫格式。
- 是否要區分「想去」和「去過」兩種狀態（目前用「去過的日期」是否留空判斷）。
- 是否需要從匯出的 JSON 匯入（還原備份）。
- 照片張數上限（暫定 6 張）與大小上限（暫定 2 MB）是否需要調整。
- 是否要定期清理沒有被任何餐廳使用的照片檔案（例如上傳到一半關掉網頁時留下的檔案）。
- 地圖是否要支援離線（需要另外規劃圖磚下載，OpenStreetMap 不允許大量預先下載）。
- 景點搜尋是否改用其他服務（例如 Google 地點搜尋，資料較完整但需要金鑰與費用）。

■ 交付物
- 網頁：夜景餐廳清單（不用登入，直接新增、修改、刪除、篩選，並可搜尋景點帶入、在地圖上查看與設定位置、加入照片、匯出 CSV／JSON），做成 PWA，可安裝到手機主畫面，用 GitHub Pages 發佈
- Supabase：資料表、照片儲存桶與存取規則（建表 SQL）
