# 夜景餐廳口袋名單｜專案規則

本資料夾是「夜景餐廳口袋名單」專案。開始任何工作前，先讀 `需求筆記.txt`。
本檔案的規則只適用於這個資料夾；儲存庫根目錄與其他資料夾的 `AGENTS.md` 屬於其他專案。

## 每次開工

1. 先把工作區更新到 GitHub 上最新的 `main`，再開始修改。
2. 確認目前分支與 `main` 沒有衝突；有衝突就先處理，不要在舊版本上繼續做。

## 金鑰與機密

- 只能使用 Supabase 的 **publishable key**（以 `sb_publishable_` 開頭）。
- **secret key 不可以寫進任何檔案**，包含程式碼、設定檔、說明文件、範例、測試與 commit 訊息。`service_role` 金鑰、資料庫密碼、個人存取權杖也一樣。
- 不要把金鑰或帳號資訊貼在 Pull Request、Issue 或留言裡。
- 若發現 secret key 已經被提交，立刻停止工作並通知負責人更換金鑰；只刪除檔案不夠，因為它還留在 Git 歷史裡。

## 權限（不用登入版）

- 需求方已確認改為不用登入：`anon` 角色可以讀取、新增、修改、刪除全部資料，任何拿到網址的人都能讀寫。
- 資料表仍必須啟用資料列安全（RLS），每個允許的操作都要寫成明確的政策；不給 `TRUNCATE`。
- 新增與修改只開放內容欄位；`id`、`created_at`、`updated_at` 由資料庫產生。
- 保留 CHECK 限制，網頁的檢查要與資料庫一致。
- 不要重新加入登入，除非需求筆記先更新；回報時提醒需求方資料是公開的。

## 資料與隱私

- 所有餐廳名稱、地址、推薦人都使用虛構資料。
- 不放真實姓名、電話、Email，也不放客戶或廠商的真實資料。
- 真實的旅遊行程（去過的日期、地點）不要放進範例、截圖、測試或公開文件。

## 檔案與命名

- 這個專案的檔案都放在 `夜景餐廳/` 資料夾內；Supabase 建表 SQL 放在 `夜景餐廳/supabase/`。
- 使用者看得到的文字使用繁體中文。
- 欄位名稱在需求筆記、資料表與程式中要保持一致。
- 需求筆記沒寫到的地方標示「待確認」，不要自行假設。

## 完成後

1. 自行檢查成果：SQL 確認語法正確；網頁在手機尺寸測試新增、修改、刪除、篩選與離線開啟。
2. 用 GitHub 外掛建立 Pull Request，標題使用繁體中文，說明變更內容與驗證方式。
3. 用 GitHub 外掛把 Pull Request 合併進 `main`。
4. 回報 Pull Request 連結與合併結果。

## 範圍

- 目前只做需求筆記列出的交付物：網頁清單（PWA）、Supabase 資料表與存取規則。
- PWA 的 Service Worker 只能快取網頁本身的檔案，不可以快取 Supabase 的資料。
- 修改網頁檔案後，把 `sw.js` 的 `CACHE` 版本號加 1，讓已安裝的 App 更新。
- 未經確認不要在 Supabase 執行 SQL；交付的是檔案，由負責人自行執行。
- 地圖、照片、匯出功能本次不做。
