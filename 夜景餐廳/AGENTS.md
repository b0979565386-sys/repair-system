# 夜景餐廳口袋名單｜專案規則

本資料夾是「夜景餐廳口袋名單」專案。開始任何工作前，先讀 `需求筆記.txt`。
本檔案的規則只適用於這個資料夾；儲存庫根目錄與其他資料夾的 `AGENTS.md` 屬於其他專案。

## 每次開工

1. 先把工作區更新到 GitHub 上最新的 `main`，再開始修改。
2. 確認目前分支與 `main` 沒有衝突；有衝突就先處理，不要在舊版本上繼續做。

## 金鑰與機密

- 只能使用 Supabase 的 **publishable key**（以 `sb_publishable_` 開頭）。
- **secret key 不可以寫進任何檔案**，包含程式碼、設定檔、說明文件、範例、測試與 commit 訊息。`service_role` 金鑰、資料庫密碼、個人存取權杖也一樣。
- 不要把金鑰或帳號資訊貼在 Pull Request、Issue 或留言裡。
- 若發現 secret key 已經被提交，立刻停止工作並通知負責人更換金鑰；只刪除檔案不夠，因為它還留在 Git 歷史裡。

## 權限（不用登入版）

- 需求方已確認改為不用登入：`anon` 角色可以讀取、新增、修改、刪除全部資料，任何拿到網址的人都能讀寫。
- 資料表仍必須啟用資料列安全（RLS），每個允許的操作都要寫成明確的政策；不給 `TRUNCATE`。
- 新增與修改只開放內容欄位；`id`、`created_at`、`updated_at` 由資料庫產生。
- 保留 CHECK 限制，網頁的檢查要與資料庫一致。
- 不要重新加入登入，除非需求筆記先更新；回報時提醒需求方資料是公開的。

## 只限臺灣

- 這個清單只收臺灣（含澎湖、金門、馬祖）的夜景餐廳。
- 縣市只能是臺灣 22 個縣市（正式寫法用「臺」）；網頁的下拉選單、`toTwCity` 與資料庫 `nvr_city_taiwan` 必須一致。
- 地圖座標必須在 緯度 21.8～26.5、經度 118.0～122.2 之間；網頁的 `TW_BOUNDS` 與資料庫 `nvr_coords_taiwan` 必須一致。
- 景點搜尋必須帶 `countrycodes=tw`，並過濾掉範圍外的結果。
- 資料庫的臺灣限制使用 `NOT VALID`，舊資料不會被拒絕，但修改時必須改成臺灣的縣市與位置。

## 資料與隱私

- 所有餐廳名稱、地址、推薦人都使用虛構資料。
- 不放真實姓名、電話、Email，也不放客戶或廠商的真實資料。
- 真實的旅遊行程（去過的日期、地點）不要放進範例、截圖、測試或公開文件。

## 檔案與命名

- 這個專案的檔案都放在 `夜景餐廳/` 資料夾內；Supabase 建表 SQL 放在 `夜景餐廳/supabase/`。
- 使用者看得到的文字使用繁體中文。
- 欄位名稱在需求筆記、資料表與程式中要保持一致。
- 需求筆記沒寫到的地方標示「待確認」，不要自行假設。

## 完成後

1. 自行檢查成果：SQL 確認語法正確；網頁在手機尺寸測試新增、修改、刪除、篩選、搜尋景點、地圖（顯示、點選位置、清除位置）、照片（加入、移除、上限、縮圖與去除 EXIF、失敗時清理）、匯出（範圍、CSV 內容與公式防護、JSON）與離線開啟。
2. 用 GitHub 外掛建立 Pull Request，標題使用繁體中文，說明變更內容與驗證方式。
3. 用 GitHub 外掛把 Pull Request 合併進 `main`。
4. 回報 Pull Request 連結與合併結果。

## 範圍

- 目前只做需求筆記列出的交付物：網頁清單（PWA）、Supabase 資料表與存取規則。
- PWA 的 Service Worker 只能快取網頁本身的檔案，不可以快取 Supabase 的資料。
- 修改網頁檔案後，把 `sw.js` 的 `CACHE` 版本號加 1，讓已安裝的 App 更新。
- 同一個網站上還有其他 App：Service Worker 只能清除以 `night-view-v` 開頭的快取，不可刪除其他 App 的快取；只處理本資料夾的檔案。
- 未經確認不要在 Supabase 執行 SQL；交付的是檔案，由負責人自行執行。
- 匯出在瀏覽器產生檔案（CSV 加 UTF-8 BOM、JSON），不經過伺服器；檔名用英文（`night-view_日期_時間`），避免部分瀏覽器把中文檔名改成「download」。
- CSV 必須逐格加引號，並在以 `= + - @` 開頭的內容前加 `'`，防止公式注入。
- 匯入（還原備份）尚未實作，需求筆記確認前不要加入。
- 照片存在 Supabase Storage 的 `night-view-photos` 公開儲存桶，資料表 `photos` 欄位只記檔名：
  - 上傳前必須在瀏覽器縮圖並重新存成 JPEG（長邊 ≤ 1600、≤ 2 MB），以去除 EXIF 定位資訊。
  - 檔名只能是網頁產生的 `UUID.jpg`，要與資料庫 CHECK 及 Storage 政策一致；不給 Storage 的 UPDATE（不能覆蓋）。
  - 先上傳照片、再寫資料表；資料表寫入失敗要刪除剛上傳的照片；資料存好後才刪除被移除的舊照片。
  - 刪除餐廳時要一併刪除它的照片。
  - Service Worker 不可快取照片。
  - 測試與截圖只能用自己產生的虛構圖片，不可用真實旅遊照片。
- 地圖使用 Leaflet（CDN 固定版本並加 SRI）與 OpenStreetMap 圖磚（免金鑰）：必須顯示「© OpenStreetMap 貢獻者」，不可預先或大量下載圖磚，Service Worker 不可快取圖磚。
- 點地圖標記直接開啟店家頁面（`#detail`）；店家頁面、標記提示與表單一律用 DOM 元素與 `textContent` 建立，不可用 HTML 字串放資料內容。
- 畫面上不可顯示經緯度數字（表單只顯示「已設定位置」）；經緯度只用於地圖標記、導航連結與匯出。
- 「我的位置」只能在使用者按下時定位，位置不可存進資料庫。
- 緯度與經度必須兩個都填或兩個都不填，網頁檢查要與資料庫的 CHECK 一致。
- 景點搜尋使用 OpenStreetMap Nominatim（免金鑰），必須遵守其使用規範：不做邊打邊搜、每秒最多一次請求、標示「© OpenStreetMap 貢獻者」。搜尋結果不可存進資料庫或離線快取，帶入表單前要裁成資料庫允許的長度。
- 若改用需要金鑰的地點搜尋服務，只能用可公開、並已限制網域的瀏覽器金鑰。
