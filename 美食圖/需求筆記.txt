公司附近午餐美食圖｜需求筆記（示範資料，全為虛構）

■ 背景
- 公司：示範公司（虛構）。
- 用途：同事每天找午餐，想知道公司附近有哪些店、走路要多久、好不好吃。
- 目前問題：推薦散在聊天群組和口耳相傳，新同事不知道附近有什麼可以吃，也看不出哪家店評價比較好。
- 想做一個「公司附近午餐美食圖」：在地圖上標出午餐店，同事可以新增店家、幫店家評分和留短評。

■ 要登記的資訊
店家：基本與位置
- 店名
- 地址
- 地圖座標（緯度、經度）
- 從公司步行幾分鐘
店家：吃什麼與價位
- 料理類型（例如：便當、麵食、飯類、輕食、異國料理、其他；選項清單待確認）
- 價位區間（例如：100 元以下、100～200 元、200 元以上；區間待確認）
- 推薦菜色
店家：營業與用餐方式
- 營業時間
- 用餐方式：內用、外帶、皆可
- 可否外送
店家：系統欄位
- 新增者（登入的同事帳號，系統自動帶入）
- 登記時間（系統自動產生）
評價（每位同事對每家店最多一筆）
- 評分（1～5 分）
- 短評
- 評分者（登入的同事帳號，系統自動帶入）
- 評分時間（系統自動產生）
- 店家清單顯示平均分數與評分人數

■ 誰能做什麼
- 未登入的人：什麼都不能看，也不能新增。
- 登入的同事：
  - 查看美食圖與店家清單。
  - 新增店家。
  - 對每家店評分並留短評，一人一家店只能有一筆評價。
- 管理者：刪除不適合或重複的店家與評價（在 Supabase 後台操作）。
- 同事能不能修改或刪除自己新增的店家、自己的評價：待確認。

■ 資料安全
- 這是示範，店家、地址、座標、人名、帳號都用虛構資料，不放真實姓名，也不放客戶或廠商的真實資料。
- 只能使用 Supabase 的 publishable key；secret key（含 service_role）不可以寫進任何檔案，也不可以上傳到 GitHub。
- 資料表必須啟用資料列安全（RLS）：只有登入的同事能讀取；新增與評分時，新增者／評分者必須是本人（auth.uid()），不能冒用他人。
- 網頁會用 GitHub Pages 發佈，頁面本身是公開的，但沒有登入就讀不到任何資料。
- Supabase 預設任何人都能自行註冊帳號；必須限制註冊（例如關閉自行註冊、改為邀請制），否則「需要登入」形同虛設。
- 同事帳號（Email）屬於個人資料：畫面上不顯示 Email，改顯示暱稱或代稱。

■ 還沒決定的事
- 登入方式：Email 魔法連結、密碼，或公司帳號單一登入。
- 帳號怎麼開通：邀請制、限定公司網域，或由管理者建立。
- 地圖服務：OpenStreetMap（免金鑰）或其他需要金鑰的地圖服務。
- 店家座標怎麼取得：在地圖上點選、手動輸入，或用地址轉換。
- 公司位置與範圍：步行時間以哪裡為起點、只收幾分鐘內的店。
- 料理類型選項、價位區間、營業時間的填寫格式。
- 同事能否修改或刪除自己新增的店家與評價。
- 誰是管理者，以及管理者是否需要網頁上的管理功能（目前在後台操作）。
- 畫面上顯示的暱稱從哪裡來。

■ 交付物
- 網頁：美食圖（登入、地圖、店家清單、新增店家、評分），用 GitHub Pages 發佈
- Supabase：資料表與存取規則（店家、評價）
- Excel：欄位表與範例資料（虛構）
